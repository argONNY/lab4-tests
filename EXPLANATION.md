## Основные понятия

| Термин | Простое объяснение |
| --- | --- |
| Unit-тест | Проверяет небольшую часть: например, проверку одной записи. |
| Интеграционный тест | Проверяет, как части работают вместе: файл → запись → результат. |
| Arrange | Подготовить входные данные. |
| Act | Вызвать проверяемую функцию. |
| Assert | Сравнить результат с ожидаемым. |
| Фикстура | Общая подготовка данных для разных тестов. |
| Параметризация | Один тест выполняется с разными наборами входов. |
| Mock / patch | Временная подмена функции для имитации ситуации. |
| tmp_path | Временная отдельная папка pytest для конкретного теста. |
| Покрытие | Какая доля строк и ветвей выполнялась в тестах. |
| CI | Автоматическая проверка проекта после отправки изменений. |

## Как читать тест

```python
def test_zero(valid_record):
    valid_record["amount"] = 0             # Arrange
    with pytest.raises(ValidationError):   # Assert: ждём конкретную ошибку
        validate_record(valid_record)     # Act
```

Если ошибки не будет или возникнет другой тип, например IndexError,
тест завершится неуспешно. InvalidTransactionError является наследником
ValidationError, поэтому проходит проверку родительского типа.

## Почему в tests нет тестовых CSV

Тест сам создаёт файл в `tmp_path`. Поэтому проверки независимы от
настоящих данных пользователя и от абсолютных путей на его компьютере.
Изменение файла в одном тесте не меняет входы другого.

## Зачем mock

```python
with patch.object(Path, "open", side_effect=PermissionError("read only")):
    with pytest.raises(DataFormatError):
        save_report(Report(), output)
```

Мы не блокируем реальный диск. Только на время блока open вызывает
PermissionError. Программа должна преобразовать её в свою DataFormatError.
После выхода из with обычный open восстанавливается автоматически.
Отдельный тест проверяет, что главный интерфейс выводит ошибку и код 1,
не печатая traceback, а старый result.json остаётся целым.

## Частые вопросы преподавателя

**Зачем тестировать ноль?** Это граница допустимых значений. В новом
задании сумма строго положительная; ноль должен вызывать ошибку.

**Почему InvalidTransactionError, а не IndexError?** Первая означает
понятную ошибку входных данных, вторая обычно указывает на ошибку кода.

**Почему 100% покрытия не гарантирует отсутствие ошибок?** Выполненная
строка могла дать неверный результат. Поэтому нужны содержательные
проверки результата, а не только вызов функции.

**Что проверяет тест с тремя строками CSV?** Создаёт хорошую строку и две
плохие, прогоняет Processor, читает сохранённый JSON и проверяет, что
массив records содержит только хорошую запись, а сумма равна 0.01.

**Чем mypy отличается от pytest?** Mypy анализирует типы без выполнения
программы. Pytest выполняет код на конкретных данных и проверяет результат.

**Что произойдёт при покрытии 79%?** Pytest вернёт ненулевой код из-за
--cov-fail-under=80, и шаг GitHub Actions завершится ошибкой.
