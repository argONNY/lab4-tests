# Лабораторная №4 — тестирование интегратора

Это самостоятельная копия проекта лабораторной №3 с pytest, покрытием,
mypy, flake8 и workflow GitHub Actions. Исходная лабораторная №3 не менялась.

## Быстрый запуск в VS Code

1. Распакуй `lab4.zip` в новое место, не внутрь предыдущей `lab3`.
2. Через **File → Open Folder** открой папку `lab4`, в которой находятся
   `main.py`, `pytest.ini`, `app` и `tests`.
3. Открой **Terminal → New Terminal**.
4. Установи инструменты тестирования (нужен интернет):

```powershell
py -m pip install -r requirements-dev.txt
```

5. Запусти проверки по очереди:

```powershell
py -m pytest -v
py -m mypy
py -m flake8 app main.py tests
```

Ожидается `85 passed`, покрытие `99.32%`, сообщение mypy об отсутствии
ошибок. Flake8 при успешной проверке ничего не выводит.
Локально проверено на Python 3.12.14 / Windows; workflow использует
Python 3.13 / Ubuntu. Твоя версия Python 3.13 подходит.

Для запуска самого приложения:

```powershell
py main.py
```

Программа обрабатывает 10 учебных файлов: 3 без ошибок, 7 с намеренными
ошибками; 5 записей принимаются. Суммы: sales = 350.00, services = 350.
Результат записывается в `result.json`, журнал — в `app.log`.
Можно передать другую папку и выходной файл:

```powershell
py main.py "C:\Reports\data" --output "C:\Reports\result.json"
```

## Что изменено по требованиям лабы №4

- В лабе №3 нулевая сумма допускалась. Здесь сумма должна быть строго
  больше нуля, поэтому `0` вызывает ошибку валидации.
- Добавлен `InvalidTransactionError`, наследующий `ValidationError`:
  мусорные данные вызывают именно доменное исключение.
- Значения `NaN`, бесконечность, переполнение/обнуление при преобразовании
  в float отклоняются. `1e308` разрешено, `1e309` отклоняется.
- Вычисление сумм сохраняет точность Decimal даже при сложении огромной
  суммы с 0.01; есть отдельный тест.
- В JSON добавлен массив `records`. Он содержит только принятые записи;
  поле `totals` по-прежнему содержит суммы по категориям.
- Добавлен `Processor`, объединяющий чтение, проверку, подсчёт и запись.

Финансовые суммы в JSON представлены строками, чтобы сохранить десятичное
представление. `currency` по умолчанию RUB; смешивание валют запрещено.
Одинаковые id не считаются дважды: принимается первая корректная запись.

## Структура тестов

```text
tests/
├── conftest.py                 # Общие фикстуры valid_record и input_dir
├── unit/
│   ├── test_validation.py      # Суммы, даты, id, мусор, обязательные поля
│   └── test_models.py          # Неизменяемость записи, независимость списков
└── integration/
    ├── test_readers.py         # Временные CSV/JSON, повреждения, доступ
    ├── test_processor.py       # Файлы → проверка → итоговый JSON
    ├── test_writer.py          # Запись, полный диск, сбой замены файла
    └── test_cli.py             # Сводка и ошибки без traceback
```

Все входные файлы тестов создаются через `tmp_path`, вне папки `tests`.
Фикстуры не изменяют учебную папку `data`. В tests остаются только исходники
и, возможно, стандартный кэш Python `__pycache__`.

## Где выполнено каждое требование

| Требование | Реализация |
| --- | --- |
| 0.01 допустимо, 0 недопустимо, большая сумма | `test_amount_boundaries` — 21 набор параметров |
| Неверная дата или id | `test_invalid_fields` — 16 наборов параметров |
| Именно InvalidTransactionError | `test_garbage_raises_domain_error_not_index_error` |
| Общая фикстура | `tests/conftest.py`: `valid_record`, `input_dir` |
| 1 хорошая и 2 плохие строки CSV | `test_csv_one_good_two_bad` |
| Только 1 запись в итоговом JSON | В этом тесте проверяются длина `records`, id и итоговая сумма |
| Имитация защищённого диска | `test_write_protected_disk`, `test_cli_reports_write_failure` |
| Сохранность старого отчёта | Тесты сбоя записи, fsync и replace |
| Не менее 80% покрытия | `--cov-branch`, `--cov-fail-under=80` в `pytest.ini` |
| HTML-отчёт | `htmlcov/index.html` |
| Проверка типов | Строгий mypy для приложения и тестов |
| Проверка стиля | Flake8 для приложения и тестов |
| GitHub Actions | `.github/workflows/quality.yml` |

Параметризованный тест запускается несколько раз с разными входами.
Поэтому 85 выполненных случаев — не 85 отдельных функций.

## Как смотреть покрытие

После pytest открой `htmlcov/index.html` в обычном браузере.
В отчёте можно нажать на имя Python-файла и посмотреть выполненные строки
и ветви. Каталоги `app/services` и `app/io` имеют 100% покрытия.
Непокрытой осталась только строка прямого запуска `sys.exit(main())`:
тесты вызывают `main()` напрямую для проверки кода возврата.
Это видно в отчёте; исключений этой строки из покрытия нет.

Отчёт включает приложение и main.py, не сами тесты.
Покрытие показывает выполнение кода, а правильность поведения проверяют
содержательные assert: суммы, записи, типы ошибок, целостность файлов.

## GitHub Actions: последний шаг для сдачи

Workflow подготовлен, но реальный зелёный запуск на GitHub ещё не выполнен:
на момент подготовки у тебя не было репозитория. Локальные проверки не
заменяют скриншот успешного запуска Actions.

Создай репозиторий `lab4-tests` на GitHub. Для первого проекта удобнее
создать его без README и других автоматически добавленных файлов.
В корне репозитория должны лежать **содержимое папки lab4**, а не архив
и не дополнительная вложенная папка lab4:

```text
.github/workflows/quality.yml
app/
data/
tests/
main.py
pytest.ini
mypy.ini
.flake8
.gitignore
requirements-dev.txt
README.md
```

Если Git уже установлен, открой терминал именно в папке lab4 и выполни
следующие команды. Вместо URL ниже подставь адрес своего репозитория:

```powershell
git init
git add .
git commit -m "Add lab 4 tests and quality checks"
git branch -M main
git remote add origin https://github.com/USERNAME/lab4-tests.git
git push -u origin main
```

При первом запуске Git может попросить настроить имя и email автора;
для отправки GitHub попросит авторизацию. Не вставляй пароль в код.
Если Git не установлен или возникнет ошибка, пришли её текст — разберём
отдельно; локально лабораторная уже работает.

После отправки открой вкладку **Actions → Python quality**.
Workflow установит Python и зависимости, запустит flake8, mypy и pytest.
Если всё прошло, рядом с запуском появится зелёная галочка.
В журнале шага pytest будет таблица покрытия и TOTAL; в Artifacts —
архив `coverage-report` с HTML/XML/JSON-отчётами.
Сохрани скриншот зелёного запуска и таблицы покрытия для сдачи.

Схема настройки основана на официальном руководстве GitHub:
https://docs.github.com/en/actions/tutorials/build-and-test-code/python
